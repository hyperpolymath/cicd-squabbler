==== Added

* `.github/actions/squabble` — a composite action that installs the
  squabble v0.1.0 release binary for other workflows and, optionally, runs
  it. It refuses any download whose sha256 is not the pinned digest, or whose
  build attestation does not name this repository's `release.yml`, the
  `v0.1.0` tag and its source commit, on a GitHub-hosted runner; nothing runs
  until both pass. `tests/squabble_action_test.sh` (27 cases, with planted
  tampered downloads and planted `action.yml` mutants) runs in the new
  `squabble-action.yml` workflow. Linux x86_64 only.
* `squabble chains` — read-only cross-repo CI dependency chains (Phase A of
  `docs/proposals/squabble-modes-and-app-layer.adoc`). Pure analysis in
  `squabble-core::chains`: cycles and dead upstreams (blocking), diamonds,
  pin skew and tag/branch pins (warnings), an upstreams-first landing order,
  and the longest chain (a max-plus longest path, hop-weighted for now).
  Sources mix freely: local checkouts, and `gh:owner/repo` read through
  GitHub GraphQL. `--follow N` probes upstreams; action repos are probed for
  existence only, and reusable-workflow upstreams contribute only the files
  actually called. New exit code `4` = blocking chain finding.
* `squabble-forge` crate — GitHub GraphQL via `gh api graphql`, batched with
  aliases, owner/name passed as variables. Every query is validated in tests
  against a committed schema snapshot (`graphql/github-schema.graphql`,
  refresh with `just graphql-schema-refresh`). Records `rateLimit` cost; an
  exhausted budget marks the remaining repos unavailable rather than guessing.
  Truncated or binary blobs and renamed repos are reported as notes.
* `scripts/install-toolchain.sh` no longer pipes a network response into a
  shell. rustup is bootstrapped from the official `rustup-init` binary whose
  published SHA-256 is fetched over TLS from the same origin and verified before
  execution; a tampered, malformed or missing digest is a refusal. Creusot is
  cloned at the commit its tag pointed to and the checkout is verified before
  `./INSTALL` runs; a version with no pinned commit is refused instead of being
  cloned from a moving tag.
* `docs/CREUSOT.adoc` — the toolchain split into the four layers that actually
  gate a verdict (manager, toolchain, `cargo creusot`, Why3 + solver), and a
  measured account of an environment that reaches only some of them: the
  `rustup` wheel on PyPI installs from an allow-listed channel, every dist
  server still refuses (`tls handshake eof`), and `rust-lang/rust` publishes no
  binary assets, so GitHub cannot stand in for one. Records what the status of
  the obligations is in that environment — unchanged — rather than a skip.
* fetch: `PinWorkflowActions`, `ReconcileActionsPolicy` and
  `SetActionsAllowedAll` moves, plus the Actions-policy why-probe
  (`actions/permissions` + `.../selected-actions`) that fires when a required
  context resolves to `STARTUP_FAILURE` — issue #15. Includes
  `examples/actions-policy-deadlock.json` offline fixture coverage.
* Structural scan now surfaces latent Actions-policy deadlocks (empty/gappy
  `selected` allowlists, tag-pinned `uses:` under `sha_pinning_required`)
  before any run refuses to start.
* ADR 0002 (`docs/decisions/`), the spec for representing vacuous greens in
  the `Outcome` contract — the spec-first remainder of issue #58.
* Zero-job `startup_failure` taxonomy (`squabble_core::startup`), with two
  first-class classes and *distinct* moves: a **moved coordinate** (a reusable
  owner/repo renamed or transferred — GitHub answers "workflow was not found"
  and creates no job) → `RepointToCanonical`, which carries the **same pin**;
  and **allow-list admission required** (the canonical coordinate is refused by
  the caller's `selected` actions allow-list; measured on `hypatia` run
  40451601571) → `AllowListAdmissionRequired`, naming the exact minimal
  `owner/repo@*` pattern. Both are invisible in PR check lists because zero jobs
  means zero check runs. Neither is a bypass: each only lets a check *start*.
  Two new `MissingCause` variants carry the same distinction to a stuck gate.
* `squabble zero-job <path[=owner/repo]>` — attribute every observed zero-job
  run: repo, workflow, coordinate as written, canonical target, required
  allow-list pattern, and the move with its sequencing. Exit `4` on any observed
  zero-job run, attributed or not; exit `0` only for the scanned window. This is
  a diagnosis surface — it edits no settings and declares nothing green. It is
  outside `squabble-contract/1.0.0`, whose four-subcommand surface and exit-code
  meanings are unchanged.
* `squabble chains` now resolves each upstream coordinate's canonical
  `full_name` through REST (`repos/{o}/{n}`, redirects followed) and compares
  **names, not pins**, flagging moved upstreams and grouping pin skew by the
  canonical name so two spellings of one upstream cannot hide a split. A dead
  upstream is found by REST even without `--follow`; `--no-canonical` skips the
  reads and records the blind spot. A moved upstream is a *warning* — a working
  redirect is a risk, not an observed failure — while the observed zero-job run
  is blocking in `zero-job`. `chains` exit semantics are unchanged, so the
  frozen `squabble-contract/1.0.0` remains accurate. `SourceCost` records the
  REST calls made.
* The Creusot complement for Rust, the twin of `spark/`:
  `verification/squabble-creusot` states six obligations over the engine's
  load-bearing invariants (acceptance, evidence, "no diagnosis is a green",
  admission, and admission-not-green) and mirrors every one as a stable-Rust
  `#[test]` against the real `squabble-core`, so drift is caught without a
  prover. The crate is its own workspace with its own
  `rust-toolchain.toml` (Creusot v0.14.0's `nightly-2026-08-03`) and
  `publish = false`, keeping the nightly-only LGPL proof library out of the
  stable `--locked` build and `cargo audit`. `.github/workflows/creusot.yml`
  calls the estate gate (`hyperpolymath/cicd-suite`'s `creusot-gate.yml`) with
  `enforce_hollow: true`, and `scripts/install-toolchain.sh` plus `just
  verify-{status,install,mirror,creusot,gate}` install and run the toolchain,
  Creusot included via upstream's `./INSTALL` (not `cargo install`).
  **Stated, not proved**: no obligation has been discharged — the authoring
  environment has no Rust toolchain at all, and this repository's `Rust CI`
  currently ends as a zero-job `startup_failure`, so CI has not compiled the
  workspace either. The estate gate's detect/theatre phases were run against
  this tree (obligations=true, claims=false, 10 contract attributes, T1/T2/T3
  clean) and its prove phase correctly reported "NO PROOF WAS PERFORMED".
* The dev container now installs the Rust toolchains it was missing (stable for
  the workspace, Creusot's pinned nightly for `verification/`), and
  `devcontainer.json` reports toolchain status on first boot. Creusot's prover
  stack (opam + Why3 + SMT) stays opt-in via `just verify-install`.

==== Fixed

* `squabble-forge` REST: an API path is now validated before it becomes an
  argument to `gh` — empty, over-long, option-looking, upward-traversing, or any
  path carrying a byte outside `[A-Za-z0-9._-/=@+~:]` (so whitespace, `;`, `&&`,
  backticks, `$()` and newlines) is refused, and `--` ends `gh`'s option list.
  Paths are built from repository slugs that originate in workflow YAML, so this
  was untrusted data reaching argv. Six new cases cover the refusals.

* verify-satisfied: a PR with an unsigned or unverified commit no longer
  reads as done when the base requires signed commits. GitHub blocks that
  merge, squash included; it is now the agent item `unverified_commits`,
  naming each commit with its signature state and author. Every PR commit's
  signature is read, paged. A classic-protection `required_signatures`
  counts as well as a ruleset one.
* workflows: step-level `- uses:` refs were never read; only job-level
  `uses:` keys were. The issue #15 Actions-policy probes therefore missed every
  step action. Two existing tests witnessed it and were failing on `main`.
* fetch: classic branch protection is read as a gate surface. Absence from
  the ruleset listing is no longer reported as "no gate"; a classic
  `branches/{b}/protection` `required_status_checks` populates the gate
  identically (contexts unioned when both mechanisms exist), and a 403 there
  is a hard error, never a no-gate — issue #100.
* `actions.lock` re-synced after Dependabot (#111) bumped `github/codeql-action`
  to v4.38.2 in `codeql.yml`; Dependabot cannot edit the lockfile, so the lock
  still pinned v4.38.0. Symptoms on `main`: Lock Sync Gate and governance
  Actions lockfile verify red, CodeQL `startup_failure` — issue #105.
* `actions.lock` desync: `standards-pipeline.yml`'s job-level reusable ref
  (`hyperpolymath/standards@ed5e3f65…`) was unlisted. Its entry and
  dependency record (with transitive closure) are now present — Lock Sync
  Gate red on `main`, issue #105.
* All 27 workflow files whose `gh actions-lock` stamp had displaced the SPDX
  header off line 1 now carry `# SPDX-License-Identifier: MPL-2.0` as byte 1
  again — `lint-workflows / Check SPDX Headers` red on `main`, issue #105.
* Unrendered template placeholder tokens (the double-brace form) across
  `.devcontainer/`, `.envrc`, `.github/SUPPORT`, `.github/.mailmap`,
  `.github/MAINTAINERS`, `.github/CODE_OF_CONDUCT.md`,
  `.github/copilot-instructions.md` and the `.machine_readable/ai/` rule files.
  (This entry must not spell the token out: the OpenSSF Compliance gate greps
  the changelog for it, and quoting it here turned that gate red on `main`.)

==== Removed
