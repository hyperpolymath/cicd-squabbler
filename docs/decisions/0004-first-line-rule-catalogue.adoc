= Architecture Decision Record: 0004-first-line-rule-catalogue

== 4. The first-line rule catalogue (ADR 0003, staging step 2)

Date: 2026-11-13

== Status

Proposed. The catalogue below collects the failure rules that estate sessions
reported on 2026-11-13, at the owner's request, through the hub. Each rule is
evidence from one or more repositories, not yet a verified general rule. When
the implementation lands, its rule table in code is authoritative and this
record lists the decisions behind it.

Amended 2026-11-13 (increment 2): twelve rules and one widened rule were added
from the evidence that the rule reconciliation thread sent after #156 merged
(hypatia#1064). The rows quote that evidence; rows marked "reconstructed" have
no run URL yet.

== Context

ADR 0003 makes the squabbler the first-line fixer: it fixes what it can fix
safely, and it refers the rest to Hypatia. Fifteen sessions reported about 40
failure patterns. Several reports describe the same failure, and two reports
corrected an earlier one. This record removes the duplicates and gives every
rule one class.

== Decision

=== Classes

[cols="1,4"]
|===
| `FIX`    | First-line fix. The squabbler opens one PR. Most fixes change CI configuration only (workflows, `actions.lock`, pins, generated files). Rules named `SQ-CODE-nn` may change code, and only when the code-fix guard below passes on the diff (owner ruling 2026-11-13, ADR 0003, PR #154: any safe code fix is first-line). A fix never edits licence or SPDX text, rulesets, or paths that `bot_directives` restrict.
| `ACT`    | First-line action without a code change: re-run one failed job once, or update a PR branch from its base by merge.
| `REFER`  | Referral to Hypatia (ADR 0003): the squabbler tells the user the problem, the fix it would suggest, the risk and the evidence Hypatia needs to reproduce it. A rule is `REFER` when the cause is not proven or the fix is not the squabbler's to make.
| `OWNER`  | Only the owner can act (a repository setting, a secret, a security decision). The squabbler reports and does nothing else.
| `NOISE`  | Not a defect (a superseded or cancelled run). The squabbler labels it and takes no action.
|===

A `FIX` or `ACT` rule becomes `REFER` when its own "refer when" condition
holds, or when its check does not pass on the PR head.

=== Guards on every `FIX` and `ACT`

. *Kill switch.* `ESTATE_AUTOFIX` must be `on`. Any other value, or no value,
  makes the squabbler report what it would do and change nothing.
. *Attempt limit.* At most 2 fix attempts per repository, rule and head
  commit, and at most 1 re-run per failed job. After that the case is `REFER`.
. *One PR.* At most one open fix PR per repository and rule, on the branch
  `squabbler/fix/<rule-id>`. A second detection updates that PR or does
  nothing.
. *Check before green.* A fix PR claims nothing until the rule's check passes
  on its head. Green still comes only from the gate's own required checks.
. *No bypass.* No admin merge, no ruleset or required-check change, no
  `--no-verify`, no force-push to a branch the squabbler did not create.
. *Code-fix guard.* A `FIX` that changes code (`SQ-CODE-nn`) is first-line only when `code_fix_is_safe` passes on its diff. The diff must not remove a line containing `assert`, add `#[ignore]`, `skip`, `xit(`, `continue-on-error: true` or `|| true`, lower a numeric threshold on a `threshold`, `min`, `max` or `coverage` line, delete a test file, add a line to `.hypatia-baseline.json` or `.hypatia-ignore`, or add a `hypatia: allow`, `nosemgrep` or `#[allow(` suppression. With no diff the case is report-only; an unsafe diff makes it `REFER`.

=== Precedence when one log matches several rules

`match_log` returns the matching ids in the order of its matcher table
(`LOG_MATCHERS` in `rules.rs`), and the caller acts on the first. The table
puts SQ-PIN-03 before SQ-RUN-01: a rate limit inside a `setup-bun` step is
fixed at its root (an exact `bun-version`) before it is re-run. When the step
is not `setup-bun`, only SQ-RUN-01 matches. Agreed with the rule
reconciliation thread; Hypatia's `api_rate_limit` is advice that defers to
SQ-PIN-03, then SQ-RUN-01.

== Consequences

* 24 rules are first-line (20 `FIX`, 4 `ACT`), 2 are referrals, 15 are
  owner-only and 3 are noise; 44 in all. Every rule names its check and its
  referral condition.
* A fix that changes code (`SQ-CODE-nn`) is first-line only when the code-fix
  guard passes on its diff, so a fix that could weaken a check never runs at
  the first line (owner ruling 2026-11-13, ADR 0003, PR #154).
* A referral carries the evidence Hypatia needs to reproduce the problem
  (repository, commit, run and job URLs, workflow, job, step, signature,
  toolchain, tool pins, what the squabbler tried, whether it reproduces on
  re-run and on base). A missing item reads `unknown`.
* Increment 1 of the implementation (classification, guards including the
  code-fix guard, the referral message and the read-only `squabble triage`)
  landed in `crates/squabble-core/src/rules.rs`. The executors (opening PRs,
  editing locks) follow.
