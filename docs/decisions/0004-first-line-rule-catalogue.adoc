= Architecture Decision Record: 0004-first-line-rule-catalogue

== 4. The first-line rule catalogue (ADR 0003, staging step 2)

Date: 2026-11-13

== Status

Proposed. The catalogue below collects the failure rules that estate sessions
reported on 2026-11-13, at the owner's request, through the hub. Each rule is
evidence from one or more repositories, not yet a verified general rule. When
the implementation lands, its rule table in code is authoritative and this
record lists the decisions behind it.

== Context

ADR 0003 makes the squabbler the first-line fixer: it fixes what it can fix
safely, and it refers the rest to Hypatia. Fifteen sessions reported about 40
failure patterns. Several reports describe the same failure, and two reports
corrected an earlier one. This record removes the duplicates and gives every
rule one class.

== Decision

=== Classes

[cols="1,4"]
|===
| `FIX`    | First-line fix. The squabbler opens one PR that changes CI configuration only (workflows, `actions.lock`, pins, generated files). It never edits tests, product code, licence or SPDX text, rulesets, or paths that `bot_directives` restrict.
| `ACT`    | First-line action without a code change: re-run one failed job once, or update a PR branch from its base by merge.
| `REFER`  | Referral to Hypatia (ADR 0003): the squabbler tells the user the problem, the fix it would suggest, and the risk. A rule is `REFER` when the fix touches code or tests, or when the cause is not proven.
| `OWNER`  | Only the owner can act (a repository setting, a secret, a security decision). The squabbler reports and does nothing else.
| `NOISE`  | Not a defect (a superseded or cancelled run). The squabbler labels it and takes no action.
|===

A `FIX` or `ACT` rule becomes `REFER` when its own "refer when" condition
holds, or when its check does not pass on the PR head.

=== Guards on every `FIX` and `ACT`

. *Kill switch.* `ESTATE_AUTOFIX` must be `on`. Any other value, or no value,
  makes the squabbler report what it would do and change nothing.
. *Attempt limit.* At most 2 fix attempts per repository, rule and head
  commit, and at most 1 re-run per failed job. After that the case is `REFER`.
. *One PR.* At most one open fix PR per repository and rule, on the branch
  `squabbler/fix/<rule-id>`. A second detection updates that PR or does
  nothing.
. *Check before green.* A fix PR claims nothing until the rule's check passes
  on its head. Green still comes only from the gate's own required checks.
. *No bypass.* No admin merge, no ruleset or required-check change, no
  `--no-verify`, no force-push to a branch the squabbler did not create.

== Consequences

* 14 rules are first-line (12 `FIX`, 2 `ACT`), 7 are referrals, 7 are
  owner-only and 3 are noise. Every rule names its check and its referral
  condition.
* Rules that change test or product code are referrals by design, so a fix
  that could weaken a check never runs at the first line.
* The implementation (staging step 2) puts this table in code, with the five
  guards, in one PR.
